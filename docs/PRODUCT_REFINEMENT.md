# NOVA product refinement audit

## Method and priorities

This is a code and documentation audit, not a user study or a claim about measured behavior. The extension has a New Tab dashboard, an action popup, Command Centre, an Assistant side panel and local Research. The main opportunities were to make the separate spaces discoverable, protect work when storage or AI setup fails, make data portability explicit, and keep the consent boundary understandable. The pass preserves the existing entry points, permissions and data stores; it does not introduce analytics, engagement loops, automatic extraction, new mandatory hosts or server-side provider keys in the client.

## Changes and rationale

- **Discoverability:** an Explore NOVA control on the dashboard links to the existing spaces, with Escape and focus restoration. The Assistant launcher preloads the window ID and calls `sidePanel.open` directly in the click handler; Chrome requires a user gesture ([Chrome side panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)). If unavailable, the UI points to the toolbar popup. The popup groups the same spaces without removing current-site controls. Opening the panel from a new tab does not grant temporary access to some other tab; the hint directs users to click NOVA on the desired page.
- **Research recovery:** a versioned JSON backup covers only Research pages and collections. It validates field types, URLs, size and version before a single IndexedDB write transaction. Matching URLs and existing collection IDs are retained, not overwritten; page-ID collisions are remapped, related IDs follow the mapping, and references to missing collections become unfiled. The confirmation, size limits and plaintext warning are explicit. Storage remains local, can be lost on extension removal and is subject to browser quota/eviction ([Chrome extension storage](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)). This backup is not an automatic sync and does not cover chats, dashboard data, preferences or wallpaper.
- **Source clarity:** Research displays the source page title/host, rechecks a changed tab on save and offers manual URL entry when opened directly. The library finishes loading before edits are allowed, so an initial empty snapshot cannot masquerade as the true library. URLs are stored as entered/normalized and may contain sensitive queries.
- **Assistant reliability and agency:** preflight checks happen before removing a typed question or adding a chat message. A missing backend leaves the question in the composer and opens settings. A failed history read does not replace saved chats with an empty conversation. Before either Assistant or a Research knowledge card transmits approved context, NOVA rechecks the source tab; a changed source requires fresh review. Generation failures provide a way to restore a question rather than immediately sending it again. These checks reduce stale-context risk but cannot make navigation and network requests atomic.
- **Clarity and accessibility:** the popup footer now describes local *site controls* instead of claiming that no page content ever leaves the device. AI still sends user-selected prompts and explicitly approved context through the configured backend. The launcher provides a keyboard-operable control with an expanded state, Escape and focus restoration, following the relevant principles in the [WAI-ARIA Authoring Practices](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/). Streaming announces a status without announcing every token, and follows new content only while the reader is near the bottom. Automated DOM checks do not establish screen-reader, contrast or real-device accessibility.
- **Failure handling:** unreachable backends receive an actionable message; incomplete streams cancel their reader. Privacy and least-privilege choices follow [Chrome's user privacy guidance](https://developer.chrome.com/docs/extensions/develop/security-privacy/user-privacy). AI output remains fallible; human review and recoverability reflect guidance such as Google's [PAIR guidebook](https://codelabs.developers.google.com/codelabs/pair-guidebook).

## Important limitations

- Backup is **unencrypted** and may contain sensitive URLs, queries, notes and generated cards. Maximum 5 MiB, 1,000 collections and 5,000 pages; an oversized library must be reduced before export. Existing collection IDs are kept, and duplicate pages are skipped rather than merged; inspect the result. Other NOVA data is not included.
- Research pages do not live-sync across extension windows, and ordinary concurrent edits can still be last-writer-wins. Different browser profiles and a web development preview have separate storage.
- Context is checked immediately before requests, but a page can still change after the check. Extraction heuristics cannot guarantee exclusion of sensitive material or prompt injection. Review every preview. Requests and answers can contain sensitive data; server operators and providers have their own handling policies.
- AI still requires a separately deployed backend, account token and server-only provider key. No real provider or deployed backend is asserted by this refinement. The extension account token in session storage can be cleared on restart, update, reload or disable.
- Real installed-Chrome behavior, permission prompts, download handling, CORS, streaming, keyboard/screen reader behavior, responsiveness and resource use must be tested manually; mocks are not a substitute.

## Automated verification

The refinement passed 106 JavaScript tests (including DOM and mocked Chrome APIs), 5 built-package checks, the production build and an npm audit with zero reported vulnerabilities. Six Django tests passed with a fake provider, and Django system checks passed. A development dashboard served HTTP successfully; it is not an extension test.

## Suggested installed-Chrome checks (not executed here)

1. Build, reload the unpacked `dist` extension and verify the dashboard launcher by mouse and keyboard, including Escape and focus. Open every space; test the Assistant when the browser lacks side-panel support and after clicking NOVA on a normal source page.
2. With test data, save from the popup, navigate or close the source, use a manual link, add notes/related sources, and reload. Export to a secure location; cancel then confirm import into a separate test profile. Test duplicate URLs, malformed and oversized files, storage errors and subsequent reload. Verify the backup does not include unrelated settings, chats or account tokens.
3. With a test backend, try absent/wrong credentials, denied origin permissions, network failures, cancellation and streams. Confirm drafts survive setup failures; change tabs or navigate after context approval and verify no request is made until fresh review. Inspect requests without using secrets. Check Research card generation the same way.
4. Regression-test Days 1–8, private/protected pages, themes, narrow windows, keyboard navigation and a screen reader; inspect console and network, and profile CPU and memory on representative hardware.
