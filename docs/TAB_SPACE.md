# NOVA Tab Space

Tab Space is a lazy, in-page view in the existing new-tab dashboard. Use **Tab Space** in the new-tab header; **Back to NOVA** returns without reloading the dashboard. Its panels inherit the existing theme, surface, accent and background tokens; the local twilight mountain banner is decorative. Gallery cards use Chrome's cached favicon endpoint with a fallback and a generated domain treatment, **not screenshots or page content**. Compact view is an alternative to Gallery; the view choice is stored under `nova:tabspaceView`. Search and other in-page state survive a switch back to Home during the same page lifetime.

## Quick switcher

Use **Switch tabs** in the dashboard header to open a Recent Apps–inspired carousel. It lists open normal Chrome tabs across windows, ordered by Chrome's `lastAccessed` timestamp when available (otherwise browser order). Swipe or use arrows to browse, click a card to switch, and choose **Open Tab Space** for the full manager. Escape closes the dialog. The control uses the existing live Chrome snapshot and the existing tab focus service; it loads only on demand and cleans up listeners when closed. At most five cards are mounted at once. Transitions animate transform and opacity, and respect NOVA's motion-off setting and the system reduced-motion preference.

The cards are decorative and use favicons, not screenshots. Private tabs are excluded. This is a Chrome extension UI, not Samsung's system task switcher: it cannot show native device apps or tabs on other devices. No new permission or background polling is added. Chrome APIs, actual touch behavior, animation smoothness, accessibility and resource usage still require installed-browser testing and profiling.

## Tabs and groups

The existing Day 6 `useBrowser` service provides an initial Chrome tabs/groups/windows/recent snapshot, consumes Chrome events and rejects stale asynchronous snapshots. It now supports suspending its listeners while Tab Space is hidden and refreshing on return; there is no interval polling. Failed snapshots block actions until Retry. Normal-window tabs only are displayed; incognito tabs are excluded. The existing `tabs`, `tabGroups`, `sessions` and `favicon` permissions are reused. Tab Space adds no permission, website host grant, history database or tab-content capture. Chrome may describe the existing `tabs` permission as access to browsing history.

Search matches title, URL, hostname and native group name; filters cover active, pinned, unpinned, muted, audible, grouped and ungrouped tabs, with group and sort controls. `/` focuses search; tab-name arrow keys move through the collection; checkboxes support shift-range selection. Use Gallery or Compact, switch to a tab, confirm closure, pin, mute, duplicate, reload or move using the card controls. Select tabs for confirmed bulk close, grouping, workspace save or moving. **Close other tabs** affects the chosen tab's window and can close the NOVA tab itself; a confirmation explains this. Chrome controls which closed items are available for recovery.

Native grouping reuses the Day 6 services and Groups panel: create, rename, color, collapse/expand, add, ungroup and ungroup an entire group (tabs stay open). Groups must be in a single window and cannot contain pinned tabs. Drag reorder is enabled only in unfiltered browser order and restricted to a single window, pinned section and group. Drag a tab to a sidebar group to add it, or use the keyboard-accessible group controls. Browser actions can partially succeed: reports distinguish failures where possible; there is no rollback or guaranteed undo. Rechecks mitigate, but cannot eliminate, races with other Chrome activity.

The gallery/list uses fixed-height virtual rows above 60 tabs and only mounts a viewport plus overscan. Cleanup suggestions are initially paged in groups of 20. This bounds rendered tab cards but does not prove a CPU, memory or latency target, and large workspace previews are not virtualized. No performance promises are made without profiling in Chrome.

## Cleanup and recovery

Nothing is closed, discarded or organized automatically. Exact duplicate candidates are credential-free HTTP(S) URLs normalized by the browser URL parser **with both query and fragment retained**. This intentionally differs from the older Command Centre's fragment-ignoring duplicate rule. A review chooses a tab to keep and the copies to close; pinned and active tabs are not preselected for closure. The keep tab and candidates are rechecked before each close; review failures and any stopped operation. HTTP(S) domain suggestions use exact hostnames and a small, transparent category map, not AI inference. Inactivity suggestions require a Chrome `lastAccessed` timestamp at least seven days old; missing timestamps are not guessed. Ungrouped and larger collections are review suggestions only. Ignore is temporary, for the current cleanup view.

Recently closed items are supplied by Chrome Sessions, not a NOVA history store. Chrome decides retention and whether restore works; no undo is promised.

## Shared workspaces

Tab Space shares the Day 6 `nova:savedSessions` local storage key and validation: up to 50 workspaces and 500 tabs per workspace. Existing records remain readable; an optional description of up to 500 characters is backward-compatible. Save the current normal window or selected normal tabs, update a saved workspace from the current window, rename, edit its description, delete it without closing open tabs, or preview and select tabs to restore. Only credential-free HTTP(S) URLs are saved, with title, pin and native group metadata. Private, internal and unsupported tabs are excluded. Full URLs, including query strings and fragments, can be sensitive; the data is local plaintext and is not encrypted or automatically backed up.

Restore is always initiated by the user. Preview the selection and choose current or new normal window and whether to skip already-open exact URLs. Open-all is possible by disabling skip; over ten selected tabs requires a confirmation. Restore reports opened, skipped and failed operations with per-item details; a new window is created only when a tab can be opened. Pins/groups may fail independently after tabs are already open. The older Command Centre and Day 9 automation calls retain their original restore defaults, including fragment-ignoring duplicate skipping. Writes are serialized within one page, but cross-page storage writes are not atomic; avoid editing the same workspaces simultaneously in multiple NOVA pages.

## Verification and known limitations

Automated coverage uses Node, jsdom and mocked Chrome APIs; production build/package checks verify files and lazy chunk boundaries. It cannot prove installed Chrome behavior, actual extension permission prompts, screen-reader accessibility, drag/drop, session recovery, favicon behavior, restart persistence, or CPU/memory performance. The development web preview has no Chrome extension APIs and intentionally shows an empty preview rather than invented tab data. No Chrome executable was available in the implementation environment.

### Manual Chrome checklist — not executed here

1. Run `npm run build`, load or reload `dist` in `chrome://extensions`, and open a normal new tab. Test **Switch tabs** with swipe, arrow keys, Escape, card activation, live tab changes, focus restoration and **Open Tab Space**; verify reduced motion and confirm private tabs are absent. Confirm Tab Space navigation, Home state, all four themes, custom colors/background, light/dark contrast, narrow windows and reduced motion.
2. In multiple normal windows, create tabs with duplicate and distinct query strings/fragments, pinned/muted/audio tabs, native groups and a private window. Confirm counts and privacy, gallery/compact persistence, search, filters, sorting, keyboard focus, shift selection and live updates from Chrome outside NOVA.
3. Test activate, confirmed close/close others, pin/unpin, mute/unmute, duplicate, reload, move to an existing/new window and bulk operations. Force a stale tab or API failure and inspect partial results. Exercise native group creation, rename, color, collapse, add/remove, full ungroup and drag/drop restrictions.
4. Review exact duplicate candidates, changing or closing the keep tab during review. Confirm query/fragment differences are not closed as duplicates, suggestions do not act without permission, and Chrome Recently closed restoration behaves as Chrome permits.
5. Save/update/rename/delete workspaces and descriptions. Test selected/all restores, skip on/off, current/new window, pinned/group metadata, protected/internal/private URLs, partial failures, extension reload and browser restart. Check older Command Centre and automation workspace behavior remains unchanged. Avoid real sensitive URLs.
6. Profile 100, 500 and 1,000+ tabs on target hardware with Chrome DevTools; check scroll, keyboard traversal and narrow layouts, idle/active CPU and memory. Regression-test the dashboard, widgets, Command Centre, website controls, Assistant/Research and automations. Inspect Console/Network. Mocks and chunk size are not a substitute for these measurements.
